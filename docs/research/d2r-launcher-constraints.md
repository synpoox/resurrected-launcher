# D2R launcher installation, launch and save constraints

Research snapshot: 2026-11-06. Resolves [Verify D2R installation, launch and save-isolation constraints](https://github.com/synpoox/launcher-clean/issues/4) for [Chart the three-product launcher specification and shared service contracts](https://github.com/synpoox/launcher-clean/issues/2).

This is evidence for a fresh Windows launcher specification, not implementation or an installation certification. PD2R is the playable first product; Project 09 and Project Forever remain upcoming. Account-free launcher install/update/offline play is the destination requirement; later co-op and hosted services must be specified separately. Nothing below establishes a shared economy or multiplayer support across all products. [Map](https://github.com/synpoox/launcher-clean/issues/2)

## Current PD2R installation and launch

The sole published release observed was `v0.1.0-alpha`, published 2026-11-05, targeting commit `3a2796a27bb94b1f336c65aa1f96f4a0ba15b970`. Its GitHub `prerelease` flag is false despite the alpha name. Therefore “Latest” or GitHub's prerelease flag is not a sufficient stability/channel policy. The current README inspected at `e256bf5d4a5d2c3b6e8e184a9863d9b84addac30` can contain later changes than the published build. [Release API](https://api.github.com/repos/synpoox/pd2-resurrected/releases/tags/v0.1.0-alpha), [README](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/README.md)

Close the game, unpack into `<game>\mods\`, and verify `mods\PD2Resurrected\PD2Resurrected.mpq\modinfo.json`. The `.mpq` here is a directory, not a second archive to unpack. The release staging code writes both root and MPQ-local `modinfo.json`, loader metadata, extended-save settings, companions and the three compiled plugins `core-rules`, `core-maps`, `core-ui` into the product folder. [Release staging source](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/tools/release.py)

PD2R's own player instructions use the loader's persistent Default Mod setting and then start `D2RLoader.exe`. The upstream direct `-mod` option supplies a cleaner basis for a three-product launch action. Do not substitute plain `D2R.exe -mod ... -txt`: PD2R characters require D2RLoader's extended format. The toolkit's observed loader notes say TXT compilation does not require `-txt` with 1.3.1. [PD2R instructions](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/README.md), [official direct launch](https://github.com/D2RLoader/wiki/blob/ccca8c729a967bd36b627a7a61c0e22c25bdbd46/players/installing-a-mod.md), [toolkit observations](https://github.com/synpoox/d2rAI-toolkit/blob/707f9df317021dad885ddd44329588742723d259/knowledge/d2rloader.md)

### Version drift and compatibility

`release.toml` records game version `3.3.0`, build `93847`, image timestamp `0x6ab3782c`, and loader `1.3.1-beta`. Plugin source states that Battle.net 93847 and Steam 94995 share that unpacked image timestamp under loader 1.3.1; unknown images install no hooks. The toolkit records the same Steam/Battle.net observation and distinguishes game version, build label, on-disk packed executable hash and loaded image compatibility. [Release configuration](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/release.toml), [RVA header](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/plugin/common/rvas_93847.h), [toolkit observations](https://github.com/synpoox/d2rAI-toolkit/blob/707f9df317021dad885ddd44329588742723d259/knowledge/d2rloader.md)

Consequently the owner must choose the supported platform/version matrix and behavior after retail auto-updates. An exact disk build/hash rejection would reject a documented equivalent Steam image; accepting every 3.3 build would claim more than this evidence proves. An unknown-image plugin declining to hook is not proof that the complete mod still plays correctly. Frozen game copies appear in development tooling, but that does not establish a supported player-facing copying, patching or downgrade mechanism. [Developer installer](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/tools/install.ps1), [plugin ADR](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/docs/adr/0004-plugins-split-by-multiplayer-scope.md)

## File and save ownership

| Path or state | Evidence and ownership implication |
|---|---|
| Retail game files and entitlement | Supplied by the user through Battle.net/Steam. Upstream requires ownership; installer source says it adds loader files without changing `D2R.exe` or other game files. Treat these as outside product updater ownership. [Download](https://d2rloader.net/download.html), [installer README](https://github.com/D2RLoader/Installer/blob/752c0afe03382d085eaee1f44656c6d2e731fedf/README.md) |
| `<game>\D2RLoader.exe`, `D2RCore.dll`, loader assets and global config | Shared installation infrastructure. Loader lifecycle must be separate from product uninstall. The global config includes the persisted selected mod. [Installer README](https://github.com/D2RLoader/Installer/blob/752c0afe03382d085eaee1f44656c6d2e731fedf/README.md), [PD2R README](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/README.md) |
| `<game>\mods\PD2Resurrected\PD2Resurrected.mpq\data`, metadata and product plugins | Release-owned payload. Replace a complete version, removing stale release-owned files rather than leaving an overlay of versions. The current manual update specifically removes `data`. [Staging and instructions](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/tools/release.py) |
| `mods\PD2Resurrected\d2rloader\config\d2rloader.toml` | Contains required extended-save mode and item-range defaults, but also player edits. Release instructions say keep an edited copy. Preservation must not silently remove required format settings. [Staging](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/tools/release.py) |
| `mods\PD2Resurrected\d2rloader\config\filter.json` | Shipped default becomes user-editable. Current extraction overwrites it; launcher policy should explicitly preserve edits or back them up. [README](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/README.md) |
| `Saved Games\Diablo II Resurrected\mods\PD2Resurrected\` | User characters and matching stash environment; outside installation ownership. Keep on update/uninstall. Extended characters cannot be loaded in retail. The PD2R ADR describes append-only identifiers, possible alpha save breaks, and a future savepath change after the first private-multiplayer release if an unavoidable break occurs. [README](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/README.md), [save ADR](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/docs/adr/0003-extended-saves-from-day-one.md) |

Upstream documents global extensions loading even with an active mod, and product-local extensions loading with that mod. Merely installing into separate `mods` folders does not eliminate interference from global plugins/patches. The release packages product-local plugins; PD2R's developer-only `tools/install.ps1` instead puts plugins in the game-wide folder, so it is not the player installer contract. [Loader guide](https://d2rloader.net/docs.html), [release staging](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/tools/release.py), [developer installer](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/tools/install.ps1)

The guide locates loader backups under `Saved Games\Diablo II Resurrected\D2RLoader Backups` and distinguishes vanilla/mod environments. The changelog records a China-specific `Diablo II Resurrected (CN)` location and `.d2rl` character sidecars. Resolve the real Windows save location/environment; do not assume `C:\Users\<name>` or treat one `.d2s` as the complete backup. This research did not test redirected Saved Games folders. [Guide](https://d2rloader.net/docs.html), [changelog](https://d2rloader.net/changelog.html)

## Artifacts, interruptions and prerequisites

The release API reports `PD2Resurrected-0.1.0-alpha.7z` as 72,790,802 bytes with SHA-256 `b6e2bfbd2ff4d451727109d12f89d4fc262dbff89e0c35b54aeff5c602d2c152`, plus `SHA256SUMS`. These are metadata observations, not a downloaded-byte verification in this investigation. The packager generates a schema-2 manifest with archive and per-file hashes, preservation paths, game/loader requirements and launch settings, but the PD2R workflow publishes only 7z files and SHA256SUMS to the release. Generated manifest/notes also appear in a temporary Actions artifact. Do not assume the public feed exposes the generated manifest. [Release API](https://api.github.com/repos/synpoox/pd2-resurrected/releases/tags/v0.1.0-alpha), [packager](https://github.com/synpoox/d2rAI-toolkit/blob/707f9df317021dad885ddd44329588742723d259/release/package_release.py), [publication workflow](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/.github/workflows/release.yml)

Derived updater requirements: download and verify before removing the playable version; validate extraction destinations; stage a complete release; stop writes while that installation is running; preserve user files; recover or roll back a failed replacement; only mark a release installed after commit. An interruption after the current documented delete-first step can leave no complete playable data. Resume, rollback, running-game coordination, disk-space policy and crash recovery for the fresh launcher remain to be specified and tested, not capabilities established by this research.

The upstream website currently offers loader `1.3.1-beta` as a ZIP and labels its automatic installer “Coming soon.” The site publishes SHA-256 `9286c6b5bff7f1043658411dbea305faa9698b6a455e6441668fc6d02c22aad7` and signing-key thumbprint `8001082E968FADAA58BF2F73EFA1810A11D0C28F`. These mutable website values need a pinned provisioning decision. [Official download page](https://d2rloader.net/download.html)

An official Windows installer repository exists, but explicitly says D2RLoader itself is closed source. Its documented algorithm validates HTTPS paths, stages size/hash-checked files, rolls back copy failures, preserves existing settings, and can require administrator rights for protected game folders. These are useful upstream constraints, not proof that its installer is currently downloadable, integrated here, or immune to power loss. Its GPL-3 installer license does not cover loader binaries. Decide whether the new launcher directs users to official installation, invokes an approved installer, or provisions an authorized pinned payload; redistribution permission is not established here. [Official installer README](https://github.com/D2RLoader/Installer/blob/752c0afe03382d085eaee1f44656c6d2e731fedf/README.md)

The loader changelog documents a Visual C++ Redistributable startup compatibility check; it does not supply a precise minimum redistributable version in the inspected material. It also documents extended `.d2s` and `.d2i` incompatibility with retail and rejects mixed loader BIN sets. The exact runtime prerequisite and repair UX therefore remain open. [Changelog](https://d2rloader.net/changelog.html)

Player distribution should consume built artifacts: PD2R's Python/CMake/Visual Studio/7-Zip/PD2-data requirements describe the build/release runner, not additional player prerequisites. Manual 7z extraction requires Windows support or 7-Zip; automated extraction needs a packaged capability chosen by the new launcher. [PD2R README](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/README.md)

## Other products and multiplayer: current evidence versus plans

Project Forever's private repository is accessible to this research. Its README says “Status: planning,” offline single-player, RotW characters only, with Classic and Lord of Destruction unsupported. Its plan targets D2R 3.3 + loader 1.3.1 and lists release progress at zero. Its current `mod.json` names `ProjectForever`, savepath `ProjectForever/`, version `0.1.0`, and `extendedSaves: false`; those are source configuration, not proof of a released or retail-compatible product. No GitHub releases were listed. Do not advertise it as installable merely because a source version exists. README (original cited snapshot unavailable), plan (original cited snapshot unavailable), configuration (original cited snapshot unavailable), [releases API](https://api.github.com/repos/synpoox/project-forever-clean/releases)

Project 09 was not found in the accessible synpoox repository listing or owner-scoped project-09 search; direct `synpoox/project-09-clean` and `synpoox/project09` requests returned 404. This means not located/access not established, not proof it does not exist. Its engine, expansion, loader, archive, save namespace and multiplayer requirements remain unknown and need the owner's repository pointer or future artifact contract. [Repository listing](https://github.com/synpoox?tab=repositories)

PD2R currently documents offline single-player with private multiplayer later. Its save ADR's future private-multiplayer compatibility rules and upstream loader TCP/IP capability do not establish a released PD2R network mode, a dedicated hosted service, or Project Forever/09 support. The launcher specification should distinguish local offline readiness from future network eligibility. [PD2R README](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/README.md), [save ADR](https://github.com/synpoox/pd2-resurrected/blob/e256bf5d4a5d2c3b6e8e184a9863d9b84addac30/docs/adr/0003-extended-saves-from-day-one.md), [loader overview](https://d2rloader.net/)

Account-free means no new launcher account for the destination journeys. Upstream still requires legitimate Battle.net or Steam ownership; this investigation did not verify entitlement caching, first-run authentication, offline token expiry, expansion detection or Steam launch environment behavior. Do not promise indefinite air-gapped startup from the absence of a launcher sign-in. [Official requirements](https://d2rloader.net/download.html)

## Owner decisions still needed

- Choose loader provisioning, distribution authorization and loader update/pinning policy; decide how a shared loader upgrade affects every installed product.
- Approve a compatibility matrix that separates marketing game version, platform build label and plugin image compatibility, plus the response when the user's retail game updates.
- Set per-product payload/user-file ownership and recovery rules, including edited filters, required loader settings, obsolete plugins and uninstall behavior.
- Publish an authoritative release/channel contract with compatibility, archive hash, preservation policy and save-break notices; decide whether to expose the existing generated schema or a new contract.
- Keep game ownership/authentication prerequisites explicit while making the launcher's own account optional for offline use.
- Obtain Project 09's source/artifact pointer and validate Forever's eventual release contract before enabling their install actions.

No code, installation, executable launch, hardware test, archive-byte verification or multiplayer test was performed. Compatibility conclusions are bounded by the cited snapshot; unknown versions, authentication and interruption behavior remain unverified.
