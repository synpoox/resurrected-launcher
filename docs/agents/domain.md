# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If these files do not exist, proceed silently. Create them through domain modeling only when terms or decisions are resolved.

## Layout

Single-context: one root `GLOSSARY.md` and root `docs/adr/`.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and test names.
Note missing concepts for domain modeling.
Explicitly flag proposals that contradict an existing ADR, naming the decision and explaining why it should be reconsidered.
